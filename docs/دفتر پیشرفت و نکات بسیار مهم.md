## ۱) وعدهٔ مرکزی

OwnLoop داشبورد عامل، log viewer یا گزارش فنی طولانی نیست.

> عامل هوش مصنوعی کد را می‌نویسد؛ انسان باید فهم، تصمیم‌گیری، تشخیص ریسک و مالکیت نگهداری آن را حفظ کند.

مسئلهٔ اصلی این است که کاربر هنگام کار عامل، توجهش را از دست می‌دهد و سراغ کار دیگری می‌رود. OwnLoop باید کار خسته‌کنندهٔ حفظ فهم را به تجربه‌ای کوتاه، جذاب و کم‌اصطکاک تبدیل کند.

چرخهٔ غیرقابل‌مذاکره:

```text
ابهام
→ پیش‌بینی یا انتخاب کاربر
→ آشکارشدن نتیجهٔ واقعی
→ شواهد قطعی
→ واکنش کوتاه
→ ثبت محلی
→ پیشرفت مالکیت انسانی
→ پایان روشن
```

هدف تجربه:

- محدود و بدون پیمایش بی‌پایان؛
- حدود ۶۰ تا ۹۰ ثانیه؛
- فارسی و موبایل‌پسند؛
- جذاب از راه کنجکاوی، کشف، کنترل و پیشرفت؛
- بدون streak، امتیاز جعلی یا طراحی اعتیادآور؛
- بدون معادل‌دانستن کلیک با فهم.

این یک شکست واقعی UX است و بابت آن درصد محصول بالا نرفته است.

قواعد:

- رابط نباید شبیه dashboard سازمانی یا فرم فنی باشد؛
- چند ثانیهٔ اول باید حس محصول جدی و باکیفیت بدهد؛

## ۳) مغز لحظه‌ها: AvalAI + LLM

> LLM مغز پیشنهاد و قاب‌بندی Momentهاست و AvalAI واسط رسمی مدل‌هاست.

### endpointهای رسمی

```text
ایران:  https://api.avalai.ir/v1
جهانی: https://api.avalai.org/v1
مسیر:  /responses
```

LLM مجاز است عنوان، سؤال، گزینه و روایت کوتاه فارسی را از Semantic Input پاک‌سازی‌شده پیشنهاد دهد؛ اما مجاز نیست Evidence ID، نتیجهٔ تست، امنیت، کامل‌بودن یا نبود ریسک را جعل کند.

مرجع حقیقت:

```text
Git + exit code + Evidence Graph + validator قطعی
```

امنیت:

- مدل hard-code نیست؛
- API key فقط در حافظهٔ daemon است؛
- در SQLite، artifact، log، diagnostics، URL یا browser storage ذخیره نمی‌شود؛
- ورودی کلید در UI uncontrolled است و پس از خواندن فوراً پاک می‌شود؛
- certification summary شامل raw request، raw response، متن خطا یا کلید نیست؛
- کلید هرگز نباید در Chat ارسال شود.

### Attention Loop واقعی

- انتخاب، reveal، evidence، ثبت، Moment بعدی و summary پایان‌دار؛

### پنل و Certification امن AvalAI

- مسیر `/?view=avalai`؛
- فقط مسیر ایران/جهانی، شناسهٔ مدل و کلید حافظه‌ای؛
- حفظ retention، diagnostics و secret-field patterns؛
- compose مستقیم request و Responses adapter موجود؛
- summary محدود و بدون secret/raw payload؛
- پوشش success، ایران/جهانی، JSON نامعتبر، timeout و response بزرگ.

### zero-state، keyboard، resume و follow-up

- provider تنظیم‌نشده → CTA به AvalAI setup؛
- provider آماده ولی بدون Run معتبر → CTA به نمای فنی؛
- کلیدهای `1` تا `3` و `Enter` با focus guard؛
- آغاز از اولین Moment مرور‌نشده و جلوگیری از ثبت دوباره؛
- stale identity به‌صورت fail-closed؛
- all-reviewed به summary صادقانه؛
- follow-up IDs از interaction state واقعی؛
- شمارنده و فهرست از یک Set مشترک؛
- حداکثر سه مورد، ترتیب projection و لینک به همان Run.

### Session Pacing محدود

- فقط Momentهای مرور‌نشده؛
- حفظ `selectedRank` و tie-break با `sourceIndex`؛
- همان مرز backend یعنی حداکثر ۷ Moment؛
- ۱۲ ثانیه برای هر Moment و حداکثر ۸۴ ثانیه؛
- پیش‌نمایش تعداد، زمان و شمارهٔ Run؛
- شروع صریح جلسه و timer از همان لحظه؛
- progress و summary مخصوص همان جلسه؛
- بدون ranking دوم، endpoint، persistence یا Moment جعلی.

### Reveal Feedback قطعی

فایل‌ها:

- `apps/web/src/attention-reveal.ts`
- `apps/web/src/attention-reveal.test.ts`
- `apps/web/src/attention-reveal.css`
- اتصال در `apps/web/src/AttentionApp.tsx`

سه وضعیت:

```text
confirmed → facts مستقیم وجود دارند و علامت هشدار یا ابهام دیده نشد
caution   → شکست، evidence gap، source partial، terminal مشکل‌دار یا attribution unavailable
unknown   → fact کافی نیست، status ناشناخته است، exit code نداریم یا attribution فقط observed است
```

قواعد:

- `caution` همیشه بر `unknown` مقدم است؛
- classifier فقط facts قطعی را می‌خواند؛
- انتخاب کاربر هیچ ورودی به classifier نیست؛
- تصمیم و risk response به درست/غلط تبدیل نمی‌شوند؛
- `confirmed` به معنی امنیت، صحت کامل یا فهم کاربر نیست؛
- banner کوتاه پیش از فهرست facts نمایش داده می‌شود؛
- هیچ API، LLM call، endpoint یا persistence تازه‌ای ساخته نشده است.

### پایداری startup ویندوز

- timeout پیش‌فرض start/stop از ۱۰ به ۳۰ ثانیه افزایش یافت؛
- override تستی، polling ۵۰ms، fail-closed و سقف ۶۰ ثانیه تغییر نکردند؛
- علت: Windows runner واقعی daemon preflight حدود ۲۳ ثانیه نیاز داشت و timeout قبلی در `ownloop start` به `start_timeout` رسید.
