## ۱) وعدهٔ مرکزی محصول

OwnLoop نباید فقط گزارش، فهرست رویدادها یا داشبورد فعالیت عامل برنامه‌نویس باشد.

وعدهٔ اصلی:

> عامل هوش مصنوعی کد را می‌نویسد؛ انسان باید فهم، تصمیم‌گیری، تشخیص ریسک و مالکیت نگهداری آن را حفظ کند.

مسئلهٔ واقعی که محصول باید حل کند:

- هنگام کار عامل، کاربر معمولاً منتظر نمی‌ماند و سراغ کار دیگری می‌رود.
- خواندن گزارش خام، تفاوت فایل‌ها و خروجی فنی خسته‌کننده است.
- در پایان، کد تحویل گرفته می‌شود اما فهم واقعی کاربر از تصمیم‌ها، ریسک‌ها و شواهد عقب می‌ماند.
- OwnLoop باید زمان انتظار را به یک تجربهٔ کوتاه، جذاب و مفید تبدیل کند.

### تجربهٔ غیرقابل‌مذاکره

```text
ابهام
→ پیش‌بینی کاربر
→ نمایش نتیجهٔ واقعی
→ شواهد
→ تصمیم یا واکنش کوتاه
→ بازخورد فوری
→ پیشرفت پوشش مالکیت انسانی
```

این تجربه باید:

- محدود و پایان‌دار باشد؛ نه خوراک بی‌پایان؛
- در حدود ۶۰ تا ۹۰ ثانیه قابل‌مصرف باشد؛
- با چند لمس یا کلید انجام شود؛
- کاربر را درگیر فهم کند، نه صرفاً سرگرم؛
- حس پاداش را از کشف، کنترل و پیشرفت بسازد؛ نه از الگوهای فریبنده؛
- روی موبایل و دسکتاپ کم‌اصطکاک باشد؛
- بدون متوقف‌کردن عامل کار کند.

### جذابیت بصری غیرقابل‌مذاکره

جذابیت فقط تزئین نیست؛ بخشی از سازوکار حفظ توجه است. تجربهٔ اصلی باید:

- در همان چند ثانیهٔ اول حس یک محصول جدی و باکیفیت بدهد؛
- سلسله‌مراتب بصری بسیار روشن، تایپوگرافی فارسی مناسب و فضای تنفسی کافی داشته باشد؛
- حرکت‌های کوتاه و هدفمند برای پیش‌بینی، آشکارسازی و پیشرفت داشته باشد؛
- روی موبایل طبیعی و لمسی باشد؛
- از ظاهر «داشبورد سازمانی»، فرم تنظیمات یا گزارش فنی فاصله بگیرد؛
- پاداش را از کشف و پیشرفت بسازد، نه شلوغی، امتیاز جعلی یا پیمایش بی‌پایان.

نمونهٔ مستقل نسخهٔ صفر از نظر منطق قابل‌آزمایش بود، اما از نظر زیبایی و کشش بصری رد شد. اتصال به React نباید همان ظاهر را کپی کند.

### مغز لحظه‌ها و AvalAI

تصمیم محصولی ثبت‌شده:

> در نسخهٔ فعلی، یک LLM مغز تولید و قاب‌بندی لحظه‌های مالکیت است و AvalAI واسط رسمی دسترسی OwnLoop به مدل‌ها خواهد بود.

مرز مسئولیت:

- LLM از ورودی کاهش‌یافته، پاک‌سازی‌شده و دارای شناسهٔ شواهد استفاده می‌کند؛
- LLM عنوان، سؤال، گزینه‌ها، روایت کوتاه و پیشنهاد تعامل را تولید می‌کند؛
- خروجی LLM فقط «پیشنهاد» است و حقیقت محسوب نمی‌شود؛
- اعتبارسنج قطعی، گراف شواهد، وضعیت گیت و خروجی آزمون‌ها مرجع حقیقت باقی می‌مانند؛
- خروجی خام ارائه‌دهنده، متن خطا و کلید API ذخیره نمی‌شوند؛
- کلید AvalAI فقط در حافظهٔ فرایند نگهداری می‌شود و با راه‌اندازی دوباره از بین می‌رود؛
- مدل قابل‌انتخاب است و یک مدل خاص به‌صورت دائمی در کد قفل نمی‌شود؛
- در این مرحله fallback چندارائه‌دهنده‌ای، بازار مدل و مسیریابی پیچیده ساخته نمی‌شود.

پایه‌های رسمی پشتیبانی‌شده:

```text
داخل ایران:  https://api.avalai.ir/v1
مسیر جهانی: https://api.avalai.org/v1
endpoint:    /responses
```

OwnLoop از مرز موجود `responses_json_v1` استفاده می‌کند؛ بنابراین برای AvalAI سرویس، صف، SDK یا معماری دوم ساخته نمی‌شود.

- اتصال به عامل برنامه‌نویس جدید؛

## ۷) نکات بسیار مهم که نباید دوباره فراموش شوند

۱. **OwnLoop داشبورد عامل نیست؛ لایهٔ مالکیت انسانی است.**  
۲. **موتور شواهد وسیله است، نه محصول نهایی.**  
۳. **محصول وقتی موفق است که انسان واقعاً توجه کند و بفهمد.**  
۴. **ریلز فقط الگوی اصطکاک پایین و ریتم سریع است؛ درگیری بی‌پایان هدف نیست.**
