## ۱) وعدهٔ مرکزی

OwnLoop داشبورد عامل یا log viewer نیست.

> عامل هوش مصنوعی کد را می‌نویسد؛ انسان باید فهم، تصمیم‌گیری، تشخیص ریسک و مالکیت نگهداری آن را حفظ کند.

چرخهٔ اصلی:

```text
ابهام
→ پیش‌بینی یا انتخاب کاربر
→ آشکارشدن نتیجهٔ واقعی
→ شواهد قطعی
→ واکنش کوتاه
→ ثبت محلی
→ پیشرفت مالکیت انسانی
→ پایان روشن
```

تجربه باید محدود، ۶۰ تا ۹۰ ثانیه‌ای، کم‌اصطکاک، موبایل‌پسند و بدون پیمایش بی‌پایان باشد.

## ۲) زیبایی و حفظ توجه

بازخورد مستقیم کاربر دربارهٔ نمونهٔ مستقل نسخهٔ صفر:

> **«خیلی زشت بود.»**

این یک شکست واقعی UX است؛ بابت آن درصد محصول بالا نرفت.

قواعد غیرقابل‌مذاکره:

- رابط نباید شبیه dashboard سازمانی یا فرم فنی باشد؛
- چند ثانیهٔ اول باید حس محصول جدی و باکیفیت بدهد؛
- تایپوگرافی فارسی، ریتم، فضای تنفسی و حرکت هدفمند مهم‌اند؛
- جذابیت باید از کشف، کنترل و پیشرفت بیاید، نه امتیاز جعلی یا اعتیاد؛
- هیچ ظاهر تازه‌ای تا آزمون مستقیم کاربر «زیبا» یا «تأییدشده» نیست.

پنل AvalAI، zero-state، میانبرها و resume از نظر کد و آزمون پذیرفته شده‌اند؛ پذیرش بصری و رفتاری هنوز صفر است.

## ۳) مغز لحظه‌ها: AvalAI + LLM

تصمیم محصولی:

> LLM مغز پیشنهاد و قاب‌بندی Momentهاست و AvalAI واسط رسمی مدل‌هاست.

### endpointهای رسمی

```text
ایران:  https://api.avalai.ir/v1
جهانی: https://api.avalai.org/v1
مسیر:  /responses
```

### مرز مسئولیت

LLM مجاز است عنوان، سؤال، گزینه و روایت کوتاه فارسی را از Semantic Input کاهش‌یافته پیشنهاد دهد.

LLM مجاز نیست:

- Evidence ID بسازد یا تغییر دهد؛
- نتیجهٔ تست، امنیت، کامل‌بودن یا نبود ریسک را جعل کند؛
- repository، transcript یا فایل خام را مستقیم بخواند؛
- فرمان یا کد اجرایی تولید کند؛
- مرجع حقیقت باشد.

مرجع حقیقت:

```text
Git + exit code + Evidence Graph + validator قطعی
```

### امنیت کلید و دادهٔ ارائه‌دهنده

- مدل hard-code نیست؛
- API key فقط در حافظهٔ daemon است؛
- کلید در SQLite، artifact، log، diagnostics، URL یا browser storage ذخیره نمی‌شود؛
- ورودی کلید در UI uncontrolled است و پس از خواندن فوراً پاک می‌شود؛
- certification summary شامل raw request، raw response، متن خطا یا کلید نیست؛
- کلید هرگز نباید در Chat ارسال شود.

## ۵) قابلیت‌های ساخته‌شده در OL-028

### AvalAI gateway و validator فارسی

- preset ایران و جهانی و مسیر `/v1/responses`؛
- prompt فارسی با claim داخلی کنترل‌شده؛
- Candidate فارسی سازگار با Evidence پذیرفته می‌شود؛
- Candidate متناقض و ادعاهای مطلق رد می‌شوند؛
- مسیر انگلیسی قبلی حفظ شده است.

### Attention Loop واقعی

- مسیر `/?view=attention`؛
- API واقعی `listRuns → getMoments → recordMomentInteraction`؛
- انتخاب، reveal، evidence، ثبت، Moment بعدی و summary پایان‌دار؛
- facts قطعی فارسی و claim داخلی مخفی؛
- responsive و reduced-motion؛
- dashboard فنی دست‌نخورده.

### پنل فارسی AvalAI

- مسیر `/?view=avalai`؛
- فقط مسیر ایران/جهانی، شناسهٔ مدل و کلید حافظه‌ای؛
- حفظ retention، diagnostics و secret-field patterns؛
- بدون localStorage، sessionStorage، endpoint یا backend تازه.

### Certification harness امن

- compose مستقیم request و Responses adapter موجود؛
- summary محدود و بدون secret/raw payload؛
- پوشش success، ایران/جهانی، JSON نامعتبر، timeout و response بزرگ.

### zero-state هدایت‌شده

- provider تنظیم‌نشده → CTA به AvalAI setup؛
- provider آماده ولی بدون Run معتبر → CTA به نمای فنی؛
- فرم توکن بی‌دلیل تکرار نمی‌شود.

### مصرف keyboard-first

- کلیدهای `1` تا `3` گزینه را انتخاب می‌کنند؛
- `Enter` reveal و سپس ثبت/ادامه می‌کند؛
- در phaseهای غیرمجاز و روی عناصر ورودی خاموش است؛
- listener یک‌بار ثبت و پاک می‌شود؛
- hint روی desktop نمایش و روی coarse pointer مخفی می‌شود.

### Resume از interaction state واقعی

فایل‌ها:

- `apps/web/src/attention-resume.ts`
- `apps/web/src/attention-resume.test.ts`
- اتصال در `apps/web/src/AttentionApp.tsx`

رفتار:

- `getMomentInteractionState` موجود پس از انتخاب Run خوانده می‌شود؛
- صرف view، evidence view یا usefulness «مرور کامل» محسوب نمی‌شود؛
- فقط پاسخ نوع‌محور معتبر است:
  - change: acknowledgement؛
  - decision: decisionResponse؛
  - risk: riskResponse؛
  - check: checkChoiceId.
- runId، validationId، displayId، sourceIndex، sourceCandidateFingerprint و momentType باید دقیقاً منطبق باشند؛
- mismatch به‌صورت `stale` و fail-closed متوقف می‌شود؛
- first-unreviewed Moment به‌صورت deterministic انتخاب می‌شود؛
- Momentهای قبلاً پاسخ‌داده‌شده دوباره ثبت نمی‌شوند؛
- Momentهای non-contiguous مرورشده skip می‌شوند؛
- completed و follow-up count از state واقعی hydrate می‌شوند؛
- all-reviewed مستقیماً summary می‌دهد؛
- زمان جلسهٔ قبلی جعل نمی‌شود و به‌صورت «— / زمان این مرور ثبت نشده» نمایش داده می‌شود؛
- CTA summary به‌جای شروع دوبارهٔ همان Momentها، اجرای تازه‌تر را بررسی می‌کند؛
- هیچ endpoint، persistence یا قرارداد تازه‌ای اضافه نشده است.
