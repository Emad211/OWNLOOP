## ۱) وعدهٔ مرکزی محصول

OwnLoop نباید فقط گزارش، فهرست رویدادها یا داشبورد فعالیت عامل برنامه‌نویس باشد.

وعدهٔ اصلی:

> عامل هوش مصنوعی کد را می‌نویسد؛ انسان باید فهم، تصمیم‌گیری، تشخیص ریسک و مالکیت نگهداری آن را حفظ کند.

مسئله‌ای که محصول باید حل کند:

- کاربر هنگام کار عامل معمولاً منتظر نمی‌ماند و سراغ کار دیگری می‌رود؛
- خواندن گزارش خام، diff و خروجی فنی خسته‌کننده است؛
- در پایان، کد تحویل گرفته می‌شود اما فهم کاربر از تصمیم‌ها، ریسک‌ها و شواهد عقب می‌ماند؛
- OwnLoop باید همان زمان انتظار را به یک تجربهٔ کوتاه، جذاب و مفید تبدیل کند.

### چرخهٔ غیرقابل‌مذاکره

```text
ابهام
→ پیش‌بینی یا انتخاب کاربر
→ آشکارشدن نتیجهٔ واقعی
→ نمایش شواهد قطعی
→ واکنش کوتاه
→ ثبت محلی
→ پیشرفت پوشش مالکیت انسانی
→ پایان روشن
```

این تجربه باید:

- محدود و پایان‌دار باشد؛ نه خوراک بی‌پایان؛
- در حدود ۶۰ تا ۹۰ ثانیه قابل‌مصرف باشد؛
- با چند لمس یا کلید انجام شود؛
- کاربر را درگیر فهم کند، نه صرفاً سرگرم؛
- پاداش را از کشف، کنترل و پیشرفت بسازد؛
- روی موبایل و دسکتاپ کم‌اصطکاک باشد؛
- بدون متوقف‌کردن عامل کار کند.

## ۲) جذابیت بصری یک الزام محصولی است

بازخورد مستقیم کاربر دربارهٔ نمونهٔ مستقل نسخهٔ صفر:

> **«خیلی زشت بود.»**

این نتیجه یک شکست واقعی تجربهٔ کاربری است. منطق فنی نمونه قابل‌آزمایش بود، اما نباید به‌عنوان موفقیت محصولی گزارش شود و بابت آن درصد تجربه بالا نرفت.

قواعد فعلی طراحی:

- ظاهر نباید شبیه داشبورد سازمانی، فرم تنظیمات یا گزارش فنی باشد؛
- همان چند ثانیهٔ اول باید حس یک محصول جدی و باکیفیت بدهد؛
- تایپوگرافی فارسی، سلسله‌مراتب بصری و فضای تنفسی باید واضح باشند؛
- حرکت فقط برای انتخاب، آشکارسازی و پیشرفت استفاده شود؛
- نسخهٔ موبایل باید طبیعی و لمسی باشد؛
- نمونهٔ ردشده نباید در React کپی شود؛
- هیچ ظاهر تازه‌ای تا مشاهده و قضاوت مستقیم کاربر «تأییدشده» نیست.

## ۳) مغز لحظه‌ها: LLM از مسیر AvalAI

تصمیم محصولی ثبت‌شده:

> یک LLM مغز تولید و قاب‌بندی لحظه‌های مالکیت است و AvalAI واسط رسمی دسترسی OwnLoop به مدل‌هاست.

### مرز مسئولیت

LLM مجاز است:

- از ورودی کاهش‌یافته و پاک‌سازی‌شده استفاده کند؛
- لحظه‌های مهم را پیشنهاد کند؛
- عنوان، سؤال، گزینه‌ها و روایت کوتاه فارسی بسازد؛
- اهمیت و confidence پیشنهادی ارائه کند.

LLM مجاز نیست:

- Evidence ID بسازد یا تغییر دهد؛
- ادعای امنیت، کامل‌بودن، صحت یا نبود ریسک کند؛
- نتیجهٔ تست یا تغییر گیت را جعل کند؛
- transcript، فایل خام یا repository را مستقیم بخواند؛
- فرمان، callback، tool call یا کد اجرایی تولید کند؛
- به‌عنوان مرجع حقیقت عمل کند.

مرجع حقیقت همچنان:

```text
Git
+ آزمون‌ها و exit code
+ Evidence Graph
+ validator قطعی
```

است.

### endpointهای رسمی AvalAI

```text
داخل ایران:  https://api.avalai.ir/v1
مسیر جهانی: https://api.avalai.org/v1
endpoint:    /responses
```

### امنیت کلید

- مدل از تنظیمات کاربر انتخاب می‌شود و hard-code نیست؛
- کلید AvalAI فقط در حافظهٔ daemon قرار می‌گیرد؛
- کلید در SQLite، artifact، Event، URL، log، diagnostics یا browser storage ذخیره نمی‌شود؛
- پس از restart باید دوباره بارگذاری شود؛
- کلید هرگز نباید در Chat ارسال شود.

### تصمیم مهم دربارهٔ زبان

برای حفظ جذابیت و صحت هم‌زمان:

- عنوان، سؤال و گزینه‌های قابل‌دیدن فارسی‌اند؛
- `claim` داخلی فعلاً زبان کنترل‌شده و کوتاه است؛
- validator فقط facts و Evidence IDهای واقعی را می‌پذیرد؛
- متن نمایشی مدل در UI مرجع حقیقت محسوب نمی‌شود.

- format: موفق؛
- lint: موفق؛
- typecheck: موفق؛
- تمام تست‌ها: موفق؛
- build: موفق.

در job ویندوز همین run نیز موارد زیر موفق شدند:

- ساخت بستهٔ verified؛
- ACL خصوصی؛
- محیط نصب جدا؛
- نصب و daemon preflight.

چرخهٔ نهایی runtime/uninstall در زمان ثبت این دفتر هنوز در حال اجرا بود. CI نهایی پس از cleanup باید مرجع نهایی قرار گیرد.
